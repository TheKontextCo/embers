# Support

Embers is an early developer preview maintained on a best-effort basis.

Before reporting a problem:

1. Check [known limitations](docs/KNOWN_LIMITATIONS.md).
2. Reproduce on the latest source or published release.
3. Remove personal note content, usernames, absolute paths, credentials, and
   access tokens from screenshots and logs.

Use the repository's issue forms:

- **Bug report** for a reproducible product or build failure.
- **Compatibility report** for macOS, hardware, permissions, speech, or folder
  format results, including successful results.

Keep feature proposals focused on a user problem and its evidence. General
setup questions may use a bug report when the documented setup path fails.

Security issues do not belong in public issues. Follow [SECURITY.md](SECURITY.md)
and use the private vulnerability-reporting route.
